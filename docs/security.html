// Security model

Secret Vault is a local handoff utility, not an internet-facing secret manager. This page states exactly what it protects and what it does not.

What it protects

  • Secret values never enter chat, model context, or application request logs.
  • HTTP request logging is disabled; values are never printed by the application.
  • Targets and uploads are created with mode 0600.
  • Writes are atomic — a partial write never leaves a half-written credential.
  • Symlink targets are rejected, so a link cannot redirect a secret into an unexpected file.
  • Uploads get random server-side names, so a supplied filename cannot escape the directory.
  • One concurrent request claims the token; later requests are rejected (409).
  • A wrong or missing token returns 404, not an error page that confirms a form exists.
  • Pages send Cache-Control: no-store, Referrer-Policy: no-referrer, X-Content-Type-Options: nosniff and a restrictive Content-Security-Policy.
  • Wildcard binds are refused unless explicitly allowed.
  • The deadline plus the single-use claim shrink the window in which a leaked link is useful.

What it does not do

  • No TLS. The built-in server speaks HTTP. Put a trusted TLS proxy in front, or use a private overlay network that encrypts transport.
  • No rotation, revocation or validation of the submitted credential.
  • No history. The process is intentionally single-use and stores no submissions.
  • No protection after the write. Once the credential lands in the target file, protecting that file and the host is your normal security posture.
  • No Windows support. Its filesystem permission and symlink semantics do not provide the POSIX guarantees this release enforces.
  • No IPv6 bind addresses.

Deployment rules

  1. Use localhost or a trusted private network such as Tailscale or a VPN.
  2. Treat the random URL as confidential until it is consumed.
  3. Never expose the server directly to the public internet.
  4. Prefer the default 15-minute deadline; shorten it when the user is already at the keyboard.
  5. Use --audit-log when you need proof that a handoff happened.
A leaked form link is only useful until it is consumed or expires. Start a new process for every value you need — never reuse a URL.

Reporting a vulnerability

Use a private GitHub security advisory on the repository. Never include a real credential in a report; use a dummy value that reproduces the issue.
